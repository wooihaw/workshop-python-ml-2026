# Modern Python Tools and Core Machine Learning Libraries — One-day Workshop

Materials for a **one-day hands-on workshop** that combines the essentials of two earlier
workshops into a single day:

- from [Workshop 1](https://github.com/wooihaw/workshop1-tools-2026) — managing a Python project with
  **uv** and versioning and publishing it with **Git** and **GitHub**;
- from [Workshop 2](https://github.com/wooihaw/workshop2-python-2026) — core Python constructs, then the
  classical ML library stack: **NumPy → pandas / matplotlib → scikit-learn**.

## Workshop structure

| Section | Topic | Checkpoint |
| --- | --- | --- |
| 1 | Projects with uv and Git — install uv, scaffold a project, `pyproject.toml` and `uv.lock`, dependencies, open the project in JupyterLab; Git identity, staging and committing, publishing to GitHub | Hands-on: uv and Git, end to end (~25 min) |
| 2 | Syntax, built-in types, collections and dictionaries | Exercise 1 — readings and collections (10 min) |
| 3 | Conditional branching, iteration, functions and modules | Exercise 2 — branching, loops and functions (15 min) |
| 4 | Exception management, tracebacks, file I/O | Exercise 3 — robust file processing, uses `readings.csv` (20 min) |
| 5 | NumPy, pandas, matplotlib, scikit-learn, saving a model | Exercise 4 — end-to-end mini workflow (25 min) |

All coding happens in **JupyterLab**: notebooks for exploring, its text editor for `.py` files,
and its terminal for `uv` and `git`. It is added to the Section 1 project with
`uv add --dev jupyterlab`, and JupyterLab's `.ipynb_checkpoints/` folders are added to `.gitignore`
before the first commit.

The day closes with a lab on `data/sensors.csv`: **load → clean → explore → model → extend**,
where *extend* means trying a second scikit-learn model and comparing the scores.

The appendix of the deck has cheat sheets for uv and Git, and symptom → cause → fix tables for
the usual setup failures (PATH, execution policy, Git identity, GitHub authentication, `.venv`
on GitHub, JupyterLab checkpoint folders and kernels).

## Before the day

Participants need:

- **A Windows laptop with administrator rights** — Git for Windows needs them to install.
- **A current web browser** — there is no separate editor; all coding happens in JupyterLab.
- **A GitHub account** with two-factor authentication already set up.
- **No separate Python install** — uv downloads the interpreter the project pins (3.14).

uv and Git are installed together in Section 1. To save time on the day, participants can
install both the evening before and pre-download the libraries:

```powershell
git clone https://github.com/wooihaw/workshop-python-ml-2026.git

uv init ai-workshop
cd ai-workshop
uv python pin 3.14
uv add numpy pandas matplotlib scikit-learn
uv add joblib jupyterlab
uv run python -c "import numpy, pandas, sklearn"
```

Then copy the repository's `data/` folder into `ai-workshop/`, so the exercises find
`data/sensors.csv` and `data/readings.csv`.

> The commands are written for Windows PowerShell, so they avoid `&&`, which Windows PowerShell 5.1
> does not accept.

## The datasets

Both files are synthetic, generated by `tools/make_datasets.py` with a fixed seed, so they are
safe to redistribute and identical for every participant.

### `data/sensors.csv`

Simulated environmental readings from six sensor nodes at 15-minute intervals, 2–4 March 2026.

| Column | Type | Notes |
|---|---|---|
| `ts` | timestamp | `YYYY-MM-DD HH:MM:SS`, parse with `pd.to_datetime` |
| `node` | string | `node-a` … `node-f`, **deliberately untidy** — mixed case and stray spaces |
| `temp_c` | float | temperature in °C, **48 values missing** |
| `hum` | float | relative humidity %, **73 values missing** |
| `t_max` | float | that node's daily maximum |
| `t_min` | float | that node's daily minimum |
| `fault` | int | 0 / 1 target for the classification lab |

| | |
|---|---|
| Rows as written | 1488 |
| Non-null `temp_c` | 1440 |
| Exact duplicate rows | 48 |
| Distinct `node` strings before / after `.str.strip().str.lower()` | 24 / 6 |
| `fault` positive rate | ≈ 25 % |
| Clean rows after `drop_duplicates()` + `dropna(subset=["temp_c"])` | 1392 |

The numbers on the *A tour of the JupyterLab window* slide reproduce exactly:

```python
import pandas as pd
df = pd.read_csv("data/sensors.csv")
df["temp_f"] = df["temp_c"] * 9 / 5 + 32
df["temp_f"].describe()
# count 1440   mean 70.4   min 61.2   max 79.8
```

### `data/readings.csv`

60 rows (`ts`, `node`, `temp_c`, `hum`) for **Exercise 3**. Nine `temp_c` values are
unparseable, each a different real-world failure: `""`, `"n/a"`, `"N/A"`, `"--"`, `"ERROR"`,
`"21,5"`, `"   "`, `"null"`, `"23.4C"`. Every one raises `ValueError` from `float()`, so a correct
solution prints **51 clean values and 9 skipped rows**.

## Notebook

`ml_mnist.ipynb` classifies MNIST digits with `StandardScaler` → `MLPClassifier(128, 64)` and ends
with a classification report and a confusion matrix. It no longer needs TensorFlow: the data is
downloaded once (~11 MB) as the same `mnist.npz` archive Keras uses, and cached in
`data/mnist.npz` (git-ignored). Run the first cells before the session if the venue's network is
unreliable.

## Regenerating the data

```bash
python tools/make_datasets.py
```

Standard library only, so it runs in any Python 3.9+ interpreter. The seed is fixed, so the
output is byte-identical every time.

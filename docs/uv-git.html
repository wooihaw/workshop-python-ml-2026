Stage 1 · 12 minutes

Create the Project with uv

Goal Give the code a pinned interpreter, a declared dependency, and a lock file.

  1. 1Make a folder for today's work
    cd $HOME\Documents
mkdir workshop
cd workshop
  2. 2Create the project
    uv init --package sensor-analytics
cd sensor-analytics

    The --package flag is what produces the src/ layout and the [project.scripts] section. Without it you get a flat main.py instead.

  3. 3Pin the interpreter
    uv python pin 3.14

    Writes .python-version, so every machine uses the same interpreter. The whole workshop uses Python 3.14.

  4. 4Add the one real dependency
    uv add numpy

    Watch pyproject.toml and uv.lock change. You never created or activated a virtual environment — uv did it for you.

  5. 5Open the project in JupyterLab
    uv add --dev jupyterlab
uv run python -m jupyterlab

    JupyterLab opens in your browser and keeps running in this PowerShell window — leave it open. --dev marks it as a tool for working on the project, not something the program needs to run. We start it through Python with python -m, not with the jupyter command: on laptops with Windows Smart App Control turned on, the jupyter launcher can be blocked with “An Application Control policy has blocked this file”.

  6. 6Replace the module with the real code
    src\sensor_analytics\__init__.py
    """sensor-analytics: summarise a set of temperature sensor readings."""

import numpy as np

READINGS = [21.4, 22.0, 23.7, 25.1, 24.6, 23.2, 22.8, 26.3, 27.0, 25.4]


def summarise() -> dict:
    """Return the count, minimum, maximum and average of the readings."""
    values = np.array(READINGS)

    return {
        "count": int(values.size),
        "min_celsius": round(float(values.min()), 2),
        "max_celsius": round(float(values.max()), 2),
        "mean_celsius": round(float(values.mean()), 2),
    }


def main() -> None:
    """Print the summary to the terminal."""
    print("Sensor Analytics")
    print("-" * 28)
    for name, value in summarise().items():
        print(f"{name:<14} {value}")

    In JupyterLab's file browser open src → sensor_analytics → __init__.py. Copy the listing with the Copy button, select everything in the file with Ctrl+A, paste, and save with Ctrl+S. The same file is in the workshop repository as starter/__init__.py.

  7. 7Run it in a JupyterLab terminal
    uv run sensor-analytics

    Open a terminal with File → New → Terminal — it starts in the project folder. Use this terminal for every command from here on, including all of Stage 2. sensor-analytics is the command name declared in [project.scripts]. uv syncs the environment to uv.lock and then runs inside it — no activate step anywhere.

Stage 2 · 15 minutes

Commit It and Publish It

Goal Record the work as history, and publish it without publishing the environment.

  1. 1Check the repository
    git status
git branch --show-current

    uv init already ran git init for you. The branch should be main.

  2. 2Prove the environment is excluded
    Add-Content .gitignore ".ipynb_checkpoints/"
git status --ignored --short

    .venv and .ipynb_checkpoints must both appear as ignored (!!), not as untracked (??). uv's .gitignore already covers .venv; the first line adds the checkpoint copies JupyterLab saves next to every file you edit. This is the most common mistake in this stage — check it before you commit, not after.

  3. 3Stage everything and read your own diff
    git add .
git diff --staged
  4. 4Make the first commit
    git commit -m "feat: summarise sensor readings"

    Use a conventional prefix: feat, fix, docs, chore, refactor.

  5. 5Create the remote repository

    On github.com choose New repository, name it sensor-analytics, and do NOT add a README or .gitignore — you already have both.

  6. 6Link it and push
    git remote add origin https://github.com/<you>/sensor-analytics.git
git push -u origin main

    A browser window opens for authentication. Your phone will be asked for the two-factor code.

  7. 7Look at the repository on GitHub

    You should see src/, pyproject.toml and uv.lock. You should NOT see .venv anywhere.

If the push will not authenticate

Do not spend the rest of the session on it. Your local commits are already safe. Carry on with Section 2, and come back to the push at a break or after the session.
